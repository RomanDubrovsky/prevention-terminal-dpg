Технический и архитектурный регламент Prevention AI

Документ для IT-аудиторов, системных архитекторов и специалистов по информационной безопасности (DevSecOps) партнеров.

Введение

Данный документ раскрывает подкапотную архитектуру платформы Prevention AI. Платформа спроектирована как High-load B2G/B2B решение с фокусом на изоляцию данных (Zero-PII), микросервисную маршрутизацию и абстракцию от конкретных LLM-вендоров.

1. Инфраструктура и Backend

Архитектура не использует монолитные серверы. Вычислительный слой оптимизирован под высокую доступность, микросервисную изоляцию и геораспределенную отказоустойчивость.

  • Стек: Python 3.12, FastAPI, Uvicorn, Asyncio.
  • Масштабирование: Автоматический скейлинг сервисов в зависимости от RPS. Проблема задержек решена через предварительный прогрев Edge-прокси.
  • Отсутствие состояния (Stateless): Контейнеры бэкенда не хранят сессии. Вся оркестрация делегирована в специализированные слои данных, что исключает утечки памяти (Memory Leaks) и позволяет перезапускать микросервисы без потери контекста чата.

2. Слой данных (Data Layer)

Используется строгая изоляция хранилищ по их назначению:

  • Транзакционная СУБД (PostgreSQL): Основная реляционная база для профилей и биллинга (строго внутри закрытого защищенного контура).
  • Supabase (PostgREST API): Управление состояниями (State Machine) диалогов в реальном времени, WebSockets-сигналы и сохранение логов сессий.
  • Аналитическое хранилище (ClickHouse): Хранилище сырой событийной аналитики (Telemetry/Analytics) для построения дашбордов Экспертного совета.

3. Безопасность и 152-ФЗ (Zero-PII Architecture)

Наибольший риск при интеграции ИИ в образовании — утечка персональных данных (ПДн) несовершеннолетних во внешние LLM.

// Механика локальной деидентификации (Zero-PII Guard)
Input: "Меня зовут Иванов Петя, +79991234567, меня травят"
Sanitizer (Local): Regex + NER (Named Entity Recognition)
To LLM: "[USER_NAME], [PHONE], меня травят"

Никакие ПДн не покидают защищенный контур. Нейросеть работает только со смысловыми конструктами (семантикой), а обратная склейка имен происходит уже на клиенте при рендеринге интерфейса.

4. LLM-Агностичность и гибкие коннекторы

Система не является жесткой оберткой над внешними нейросетями. Базовые языковые модели используются исключительно как «лингвистические процессоры» в конце пайплайна.

  • Модуль промптинга абстрагирован (Adapter Pattern).
  • Добавление GigaChat Pro / Lite в качестве основного коннектора требует изменения лишь конфигурации коннектора (URL API и формат payload), без переписывания логики.
  • Системные промпты, RAG-база и графы переходов хранятся на нашей стороне (в PostgreSQL) и независимы от модели.

5. ИИ-Оркестрация (Мультиагентный RAG)

Генерация протоколов и ответов работает через асинхронных агентов. Вместо одного «умного» промпта запрос проходит цепочку:

  • Agent 1 (Chat Guard): Эвристика. Блокирует Jailbreak (пэйлоады типа "ignore previous instructions"). Время ответа: ~5ms.
  • Agent 2 (Classifier): Анализирует суть. Если это острый кризис (суицид), немедленно прерывает генерацию и возвращает хардкодный медицинский ФГОС-протокол.
  • Agent 3 (RAG Retriever): Извлекает таксономию FBA (Функциональная оценка поведения) из базы знаний (векторный поиск).
  • Agent 4 (Generator): Форматирует итоговый ответ для пользователя, опираясь строго на выданную базу знаний (сводит галлюцинации к нулю).

6. Методологическое соуправление (Governance)

Мы разделяем «Движок» (программный код) и «Контент» (базу знаний, матрицы поведения). Управление платформой не требует открытых исходных кодов. Изменение протоколов, добавление новых рекомендаций и корректировка тона ИИ осуществляется через закрытую Административную панель Экспертного совета. Это позволяет партнерам (фондам, министерствам) коллегиально управлять логикой системы в формате No-Code без прямого вмешательства разработчиков.
